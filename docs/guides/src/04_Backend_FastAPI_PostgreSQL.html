2. Lancer le projet (Windows, Git Bash)

Pas de make installé ? Voici les commandes équivalentes. Le port Postgres est 5434 (5432/5433 déjà pris sur certaines machines).

cp .env.example .env
docker compose up -d --wait db              # make up
cd backend
uv sync                                     # installe les dépendances (première fois)
uv run alembic upgrade head                 # make migrate
uv run python -m pipeline.ingest --mock     # make seed (données [MOCK])
uv run uvicorn app.main:app --reload --port 8000   # make api → http://localhost:8000/docs
cd ../web && pnpm install && pnpm dev        # make web → http://localhost:3000
Bon à savoir

Si la base est vide ou arrêtée, les routes d'expériences renvoient les données mock intégrées : le front fonctionne toujours. GET /health indique db: true/false.

3. Les briques à comprendre

FastAPI + Pydantic

Une route = une fonction décorée. Les types Python deviennent validation automatique et documentation :

@router.get("/experiments/{code}", response_model=ExperimentDetail)
def get_experiment(code: str, session: Session = Depends(get_session)) -> ExperimentDetail:
    exp = catalog.get_experiment(session, code)
    if exp is None:
        raise HTTPException(status_code=404, detail=f"Experiment '{code}' not found")
    return exp

SQLAlchemy 2

Modèles déclarés avec Mapped[...] et mapped_column ; requêtes avec select() ; selectinload pour charger les relations sans requêtes en cascade.

Alembic

Toute modification de table passe par une migration, jamais à la main :

uv run alembic revision --autogenerate -m "add source_url to experiments"
# relire le fichier généré dans alembic/versions/ !
uv run alembic upgrade head

pgvector

Type vector(N) pour stocker les embeddings, opérateur <=> pour la distance cosinus, index HNSW pour aller vite (détails : guide 03).

4. Recette : ajouter une donnée de bout en bout

Exemple : afficher la « limite » d'un constat (demandée par le Guide d'équipe).

  1. models.py : limits: Mapped[str | None] = mapped_column(Text) sur Finding.
  2. Migration Alembic (autogenerate, relire, upgrade).
  3. schemas.py : limits: str | None = None dans FindingOut.
  4. services/catalog.py : remplir le champ dans _to_detail.
  5. Test pytest qui vérifie la présence du champ.
  6. API lancée → cd web && pnpm gen:types : le type TypeScript est régénéré.
  7. Le front utilise finding.limits — TypeScript signale toute erreur.

cd backend

cd ../web && pnpm lint && pnpm typecheck && pnpm build
  • Branches : main protégée, une branche feat/<nom> par personne, merge à chaque jalon.
  • Commits conventionnels : feat:, fix:, chore:, docs:.
  • Jamais de clé API ni de PDF dans Git.

6. Pièges déjà rencontrés

  • Port déjà utilisé : changer POSTGRES_PORT et DATABASE_URL dans .env.
  • Changer EMBEDDING_DIM après la migration → recréer la base (docker compose down -v).
  • uv introuvable : il est installé dans %APPDATA%\Python\Python314\Scripts ; l'ajouter au PATH.
  • Réseau lent : les installations pnpm/uv peuvent prendre 15 min ; les lancer à l'avance.
