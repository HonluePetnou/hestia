2. NTRS : déjà automatisé

Le script backend/pipeline/fetch_ntrs.py interroge l'API de recherche avec les requêtes de backend/pipeline/queries.txt, déduplique, écrit data/ntrs/catalog.csv et télécharge les PDF.

# depuis backend/ (Windows : pas de make → commandes directes)
uv run python -m pipeline.fetch_ntrs --max-per-query 15 --max-total 40
uv run python -m pipeline.extract_text          # → data/ntrs/text/<id>.jsonl + extraction_report.csv
  • Une requête de recherche : GET https://ntrs.nasa.gov/api/citations/search?q=...&page.size=15
  • Chaque résultat contient id, title, authorAffiliations, publications[].publicationDate et downloads[].links.pdf.
  • Fiche lisible par un humain : https://ntrs.nasa.gov/citations/<id> — c'est le lien affiché à côté de chaque citation.
État actuel

40 notices, 37 PDF (204 Mo, non versionnés), 36 avec texte exploitable. Le rapport extraction_report.csv marque low_text un PDF probablement scanné (20210015913) : à exclure ou à passer en OCR.

Exercice — élargir le corpus (P2)

Ajouter dans queries.txt 3 requêtes ciblées (ex. « SoFIE solid fuel ignition », « FLEX-2 cool flame », « lunar gravity flammability »), relancer le script, puis ouvrir catalog.csv et supprimer les notices hors sujet. Garder 2 à 3 familles d'expériences (conseil du Guide d'équipe).

3. PSI : la partie manuelle

  1. Ouvrir psi.nasa.gov, chercher l'investigation (exemples : FLEX PSI-69, SAFFIRE-I PSI-98).
  2. Télécharger uniquement les métadonnées et les tableaux d'essais (CSV/XLSX). Pas de vidéos ni de données brutes de capteurs.
  3. Ranger dans data/psi/<CODE>/ (ex. data/psi/FLEX/metadata.json, test_matrix.csv).
  4. Noter le DOI de l'investigation → colonne experiments.psi_doi.
  5. Noter les conditions d'accès et la licence (CC0 pour PSI).

Protocole anti-erreurs (2 personnes)
  • Couper la table en deux moitiés ; chacun transcrit la sienne.
  • Chacun relit 10 lignes au hasard de l'autre, contre le PDF.
  • Script de contrôle pandas (ci-dessous) avant tout commit.
import pandas as pd
df = pd.read_csv("data/flex/flex_table_ix.csv")
print(df.shape, df["outcome"].value_counts(dropna=False))
assert df["outcome"].isin(["extinction", "disruption", "complete_burn", "unknown"]).all()
gas = df[["o2_mole_fraction", "co2_mole_fraction", "n2_mole_fraction"]].fillna(0).sum(axis=1)
print("lignes à vérifier (somme gaz) :", df[(gas < 0.9) | (gas > 1.01)]["test_id"].tolist())
print(df.describe())   # repérer les valeurs aberrantes (diamètre 30 au lieu de 3.0…)

Valeurs autorisées : gravity ∈ {microgravity, lunar, martian, earth} ; outcome ∈ {spread, extinction, disruption, complete_burn, unknown}. Le champ extra (JSON) accueille ce qui ne rentre pas ailleurs (ex. diluant hélium).

6. Règles de qualité (non négociables)

  • Unité dans le nom de colonne (pressure_kpa, burn_rate_k_mm2_s) et une seule unité par colonne.
  • Pas de valeur inventée : case vide → affichée « non renseigné » / « — » dans l'interface.
  • Traçabilité : toute ligne doit pouvoir remonter à un document et une page.
  • Comparabilité : deux essais ne sont comparés que si leurs conditions sont définies de la même façon.
  • Pas de PDF ni de gros fichiers dans Git (déjà protégé par .gitignore).
