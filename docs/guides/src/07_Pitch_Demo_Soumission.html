Raconter Hestia en 30 secondes

Le scénario de démo, le script vidéo, les 7 slides, les règles de marque Space Apps et la check-list de soumission.

Temps : ~1 h 30 + répétitionsLivrable : vidéo 30 s ou 7 slides max

1. Ce que le jury doit retenir

  1. Le problème : les résultats NASA sur le feu en microgravité sont dispersés dans des centaines de rapports.
  2. La solution : Hestia les résume, les classe pour la Lune et Mars et les explique — avec la source.
  3. La confiance : chaque réponse cite [NTRS-ID, p.X] ; si les sources ne suffisent pas, Hestia le dit.

Les critères de jugement officiels sont publiés sur spaceappschallenge.org : les lire ensemble et cocher, pour chacun, quel moment de la démo y répond.

Tournage

Enregistrer l'écran en 1440 × 1024 ou 1920 × 1080, données réelles chargées (pas de [MOCK] visible). Prévoir un enregistrement de secours la veille. Sous-titres en anglais (règle du projet : tout en anglais).

4. Les 7 slides (si format slides)

  1. Titre : Hestia — Guarding the flame beyond Earth · équipe black-vortex · Douala.
  2. Problème : feu en cabine, savoir NASA dispersé, missions Lune/Mars.
  3. Solution : capture de l'Overview + 3 verbes : résumer, classer, expliquer.
  4. Démo : réponse citée + source NTRS ouverte.
  5. Comment ça marche : NTRS/PSI/FLEX → pipeline → RAG (pgvector) → dashboard. Chiffres réels (rapports, passages, essais).
  6. Confiance et limites : citations vérifiées, « insufficient data », grille de score, limites du modèle FLEX.
  7. Impact et suite : utilisateurs (ingénieurs matériaux, planificateurs de mission), prochaines données (SoFIE, Saffire VI).

5. Règles de marque Space Apps (brand guide, juin 2026)

  • Notre produit garde son identité (braise, Unbounded/Inter) ; le guide encadre l'usage de la marque Space Apps.
  • Logo Space Apps : fichiers officiels de spaceappschallenge.org/brand, sans le déformer, le tourner ni changer ses couleurs, et jamais sur un fond chargé (pas sur le champ d'étoiles) → zone sombre unie.
  • Pas de branding officiel NASA (logo « meatball », insignes). Écrire « NASA data » en texte est correct.
  • Slides aux couleurs Space Apps (optionnel) : dégradé Electric Blue #0042A6 → Deep Blue #07173F à 45°, Neon Yellow #EAFE07 en accent uniquement, polices Fira Sans / Overpass.
  • Contraste ≥ 4,5:1 sur tout texte.

6. Check-list de soumission

  • Dépôt GitHub accessible au jury (passer en public au moment de soumettre) avec README à jour.
  • Aucun secret dans le dépôt (.env ignoré, clés révoquées si exposées).
  • Vidéo / slides respectant la limite (30 s ou 7 slides).
  • Liste des données NASA utilisées avec liens (README, section Data sources).
  • Mention : « Not endorsed by NASA ». Données NASA : domaine public / CC0.
  • Tous les liens testés depuis un navigateur privé.
  • Formulaire de soumission rempli avant l'échéance locale (vérifier l'heure exacte).

7. Plan B (le jour J)

  • Internet ou clé API en panne → LLM_PROVIDER=mock + vidéo pré-enregistrée.
  • Base de données indisponible → l'API sert les données mock intégrées ; le site reste navigable.
  • Une personne absente → chacun connaît le parcours de démo complet (répéter 3 fois en équipe).
