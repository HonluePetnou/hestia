2. Composants serveur vs client

  • Par défaut, un composant est « serveur » : il peut appeler l'API directement (await api.listExperiments()) et n'envoie pas de JavaScript au navigateur.
  • "use client" en tête de fichier quand il faut de l'interactivité : useState, clics, formulaires, 3D (FilterBar, AssistantChat, Simulator, TopBar).
  • Next 16 + cacheComponents : toute donnée non mise en cache (fetch no-store, searchParams, params) doit être lue dans un <Suspense>. Sinon : erreur « blocking route ». Modèle utilisé partout :
async function Grid({ searchParams }) {          // lit les données
  const { data, error } = await attempt(api.listExperiments(...));
  if (!data) return <ErrorBox error={error} />;
  return ...;
}
export default function Page(props) {
  return <Suspense fallback={<Loading />}><Grid searchParams={props.searchParams} /></Suspense>;
}

4. Brancher une vraie donnée

  1. La route existe dans l'API ? Sinon la créer (guide 04).
  2. API lancée → pnpm gen:types régénère lib/api-types.ts.
  3. Ajouter une fonction dans lib/api.ts (typée avec Schemas["…"]).
  4. L'appeler dans un composant serveur, dans un <Suspense>.
  5. Remplacer le contenu SAMPLE correspondant de lib/content.ts.

5. Graphiques et 3D

Recharts

Exemple : components/BurnRateChart.tsx (nuage de points K vs O₂). Composant client, ResponsiveContainer dans un conteneur de hauteur fixe. Utiliser des couleurs hexadécimales dans les props (attributs SVG), pas var(--…).

React Three Fiber

  • <Canvas> = la scène ; <mesh> = un objet (géométrie + matériau) ; <OrbitControls/> (drei) = rotation/zoom à la souris.
  • Chargé avec dynamic(() => import(...), { ssr: false }) car WebGL n'existe pas côté serveur.
  • La taille de la goutte suit la loi en d² (guide 01) pendant la lecture de la timeline.
